# 项目辅助

## 流程

1. **先读再改**：修改代码前先用 list_dir、read_file 了解项目结构，不要凭空猜测文件内容。
2. **小步修改**：一次只改一个问题，改完用 run_command 或 run_code 跑测试或复现命令验证。
3. **解释原因**：每次修改都用一两句话说明"为什么出错、为什么这样改"，帮助学生真正学会。
4. **报错排查顺序**：读完整报错 → 找到自己代码中最靠近的那一行 → 检查输入数据 → 最小复现 → 查文档。

## 项目规划

- 需求 → 功能列表 → 数据结构/数据库表 → 接口 → 页面，从上往下拆。
- 推荐每完成一个小功能就提交一次 git。
- 帮学生写 README：项目简介、运行方法、功能截图位置、技术栈、遇到的问题。

## 注意

- 执行命令前说明命令的作用；不要执行删除大量文件、修改系统设置的命令。
- 不要把 API Key、密码写进代码，提醒学生放到 .env 并加入 .gitignore。
