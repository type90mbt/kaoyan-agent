# 00 整体架构：这个软件由哪几块组成

## 一句话

电脑上跑一个 **Python 本地引擎**，它是"大脑的身体"：保存数据、调用大模型、执行工具。桌面界面和手机 App 都只是它的"遥控器"和"随身小本"。

## 各部分的分工

| 部分 | 运行在哪里 | 负责什么 |
| --- | --- | --- |
| `engine/` | 你的电脑（后台进程） | 课件解析、检索、和大模型对话、skill、操作电脑、学习数据 |
| `desktop/` | 你的电脑（窗口） | 三栏界面：左边课程树，中间课件，右边 AI 对话 |
| `mobile/` | 安卓手机 | 今日任务、课表、提醒、打卡、刷卡片、随身问答 |
| `sync-server/` | 你自己的服务器（可选） | 让手机在外面也能和电脑同步 |

## 为什么叫"本地优先"

数据先存在本机（电脑上的 SQLite 文件，手机上的 SQLite 文件），不依赖任何服务器。需要同步时，两边交换"自上次同步以来改过的记录"。这样：

- 没网也能用；
- 别人装了就能用，不需要你帮他们开服务器；
- 隐私数据在用户自己手里。

## 一次提问的完整流程

1. 你在右栏输入问题，桌面端把它发给引擎的 `/api/chat`。
2. 引擎的 **harness** 组装上下文：系统提示词 + 选中的 skill + 本课之前的总结 + 从课件里检索到的相关片段。
3. 模型网关把请求发给 DeepSeek（或你配置的其他模型）。
4. 如果模型决定调用工具（比如"写一个 Word 文件"），先经过 **权限层** 检查，需要时弹窗让你确认。
5. 回答以"流式"方式一个字一个字传回界面。

## 关键词

- **harness**：把"模型 + 提示词 + 工具 + 记忆"组装起来跑的那层框架，类似 Cursor、Claude Code、DSH 本身。
- **RAG（检索增强生成）**：先从课件里搜出相关段落，再让模型基于这些段落回答，减少胡编。
- **skill**：一段 Markdown 写的"专项说明书"，告诉模型在某类任务里该怎么做。
